## What changed in the local playbook

The transferable rules were added to `core/engineering.md` and `workflows/development.md`: minimize unnecessary changes, scale planning to risk and ambiguity, make reports evidence-based and easy to scan, scope security claims, preserve facts and voice in prose, use diagrams selectively, and verify UI as rendered UI when applicable. `README.md` now explains which rules are always available and which skills require host discovery. `SOURCES.md` links this source audit and distinguishes it from the central playbook's pinned upstream release.

No third-party skill files, application code, hooks, scripts, package dependencies, prompts requiring access broadening, or generated indexes were copied. At the time of the initial repository review, the central playbook was version `0.2.0`, pinned to `84d5de5b81627c5b41589327e08f6a8c3e4cff76`. The curated guidance was subsequently integrated into the central playbook's `0.3.0` release at commit `55622c9717b7e4292d72dac18fac57065dd19e6b`; this project now pins that release in `.ai-playbook/VERSION`, `SOURCES.md`, and `README.md`.

## Automatic use without naming a skill

Yes, the always-loaded rules can guide a task without the user naming a skill, as long as the agent reads the project's entry instructions. This repository's `AGENTS.md` points agents to the engineering and development documents. A compatible agent following those instructions therefore sees the relevant principles without a skill invocation.

That does **not** mean every project will automatically activate every copied skill. Discovery varies by agent and version: some read root `AGENTS.md`, some support `.agents/skills`, and some require another folder, explicit configuration, installation or a restart. A skill is usually loaded only if its description matches the task or it is invoked. Copying `.ai-playbook` by itself does not make the agent read all files. Each consuming project needs a short root instruction that points to the right shared docs and real project context; each agent host needs its native skill path if on-demand skills are wanted. Verify this with a task that should trigger the behavior. Do not install hooks or plugins to simulate guaranteed auto-loading without reviewing their trust and permission effects.

## Validation and limits

- Repo names and September ranking were cross-checked against the source post; the repositories themselves were reviewed through their GitHub documentation and repository pages.
- The commit SHAs above identify the exact repository snapshots reviewed in this research session. They are not endorsements and do not imply a complete audit of each codebase, license, issue tracker or historical change.
- This is a curated guidance update, not a security certification or benchmark. The project-specific rules in `AGENTS.md`, `project-context.md`, platform workflows and active sandbox continue to take precedence.
- For future reuse, keep the shared always-on rules short, place domain procedures in on-demand skills, and confirm actual discovery in every target agent. A copied folder is not an integration test.
